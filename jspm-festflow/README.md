# JSPM Pulse

A responsive, animated single-page campus event hub for JSPM University, Pune. Built with React 19, TypeScript, the Next.js App Router-compatible Vinext runtime, Tailwind CSS, Radix/Shadcn, Lucide and CSS motion. Includes campus events, concept-based fuzzy search, calendar exports, QR passes, profile editing, bookmarks and a simulated vision upload workflow.

## Run locally

Use Node.js 22.13 or newer.

```sh
npm ci
npm run dev
```

The development preview uses port 5173. Run `npm run build` for the deployment bundle. Type-check with `npx tsc --noEmit`. Run behavior checks with `node scripts/verify-pulse.mjs` and database integration checks with `node scripts/verify-database.mjs` (mock HTTP, no live writes).

## Supabase connection

Replace the placeholders in the ignored project-root `.env.local` with your actual `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, then restart the development server. `src/lib/supabase.ts` exports the client. `src/lib/pulse-database.ts` owns table queries and mapping.

- `events`: `id` UUID (generated by the database), `title`, `tagline`, `category`, `venue`, `start_date` timestamptz, `total_capacity`, `registered_count`, nullable `image_url`, and `created_at`.
- `bookmarks`: `id`, `user_id` text, `event_id` UUID FK, lowercase `status` (`interested`, `registered`, `attending`), and `created_at`. A unique constraint on `(user_id, event_id)` is required for upserts.
- Mounting fetches `events.select('*')` and bookmarks filtered by the persistent `jspm_student_user_id` localStorage value. There is no Supabase Auth login in this demo, as requested. The configured anon SELECT/INSERT/UPDATE/DELETE policies govern the writes.
- Bookmark insertion defaults to `interested`. Changing attendance upserts the same row; removing a bookmark deletes that row and clears attendance. Optimistic activity changes roll back on errors, per-event locks prevent overlapping writes, and failed inserts keep the review form open.
- The application displays only Supabase event records; there is no event seed, local event cache, or sample fallback. A successful empty query displays the organizer invitation and Post an event button. Missing configuration and failed queries have separate connection/error messages. Existing live cards remain visible during a failed refresh.
- Enable `events` in Supabase Database → Replication / Realtime publication. The `events-channel` listener refetches for INSERT/UPDATE/DELETE and reconnection; channels are removed on cleanup. Optional bookmark realtime updates are filtered by `user_id` when that table is also enabled. Focus, visibility, and online events refetch both tables, including missed bookmark deletes.
- The supplied schema has no end time, department, prize, external registration URL, eligibility, or fee columns. Cards use neutral defaults for those fields; duration is explicitly assumed to be 3 hours. Review saves the description to `tagline` and the resized uploaded poster to `image_url` as a data URL. Registration capacity displays the database `registered_count` without adding a device-local increment. Changing bookmark status does not itself alter that count; transactional capacity enforcement requires database logic.

The anon/demo identity strategy is for this public demo. The device ID scopes client queries; it is not an authenticated student identity.

## Persistence and demo boundaries

Profile, aura, notification preferences, and teammate opt-ins stay in `localStorage` under `jspm-pulse-v1`. Live events and bookmark/attendance rows come from Supabase; old locally saved events and activity are not restored or uploaded. Uploaded posters are resized on-device and included in an event insert only when the student publishes. The persistent demo identity is stored separately under `jspm_student_user_id`.

- Registration and QR tickets are demonstrations; production admission requires organizer authentication, a shared transactional capacity store and signed ticket verification.
- Vision scanning is explicitly simulated. It runs for two seconds and suggests only a title and category from the filename. Schedule, venue and summary start blank and must be supplied by the organizer. Manual entry without a poster is also available. It does not perform OCR.
- Browser reminders require permission and an open tab. ICS files include a one-hour VALARM; reliable background web push would require a backend and service worker.
- The camera is optional and requests access only after selecting Take a photo. Tracks stop on cancel or modal close.
- Motion respects `prefers-reduced-motion`. Dialogs and drawers trap focus, support Escape and expose accessible labels.
- Google Calendar opens a prefilled draft; the user saves the event in Google Calendar. ICS downloads can be imported into Apple Calendar, Outlook and compatible calendar clients.

## Browser agent tools

Feature-detected WebMCP tools expose `search_campus_events` (read-only) and `bookmark_campus_events` (Supabase mutation). Inputs are validated, unknown IDs fail before any state mutation, tool calls wait for database writes and return saved/failed IDs, and tool registration is cleaned up with an AbortSignal.
The four-unit live countdown is isolated in `hooks/use-countdown.ts`; it updates each second, clamps elapsed events to zero and clears its timer on unmount. Hackathon and gaming cards offer a teammate board with local opt-in state and explicitly labeled sample listings. Card borders follow mouse position, ambient violet/cyan light sits behind the grid, and interest/registration/bookmark interactions celebrate with reduced-motion-aware canvas confetti.

Calendar downloads use a validated, same-origin HTTP attachment endpoint (`app/api/calendar/route.ts`) for compatibility with browsers that do not support blob downloads. Only the selected event's schedule, title, description, venue and organizer are sent to this endpoint. Profiles and uploaded posters are not included. The calendar data is not stored on the server.
